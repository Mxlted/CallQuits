# Implementation notes

CallQuits separates a deterministic decision policy (`Sources/CallQuitsCore`) from macOS integration and presentation (`Sources/CallQuits`). SwiftPM tests the policy without needing Accessibility permission or terminating a process.

## One explicit gesture, one bounded decision

1. A public Core Graphics event tap at `.cgAnnotatedSessionEventTap`, placed at `.tailAppendEventTap` with `.listenOnly`, observes original left-button down, up, and drag events. A key-down event only cancels pending work; its keycode, characters, and recipient are never read or recorded. The tap cannot change or suppress input.
2. `EventIdentity` establishes the original recipient from the native `CGEvent` target process ID or a WindowServer owner lookup for the exact global window ID stamped into that event. Accessibility hit testing must then identify the actual close control and an owner matching that established process. Missing or conflicting metadata means no action.
3. Mouse-up must confirm the original event identity and match the mouse-down's supported modifier intent. If native close already removed the original window's WindowServer entry, an exact matching stamped window ID can carry forward the previously verified owner. A conflicting positive process ID, window ID, or owner always cancels. Dragging away, a long hold, bypass modifiers, exclusion changes, and new interactions also invalidate the gesture.
4. For a normal quit, a short-lived Accessibility observer subscribes to the target app's window-created notifications. Registration must succeed; unsupported apps are skipped. Sheet-created notifications are also requested where supported, and snapshots check for sheets independently.
5. Normal mode lets the target handle its close. Bounded snapshots verify the original window disappeared, check for sheets and replacement windows, and count all reported windows, including minimized windows and other Spaces. A creation notification invalidates the pending request, including when a new window appears between snapshots.
6. After a stable eligible result, the adapter requests graceful termination. The target app retains its native save/quit behavior. Explicitly enabled Shift-click uses the separate force-termination path after gesture and target verification; it does not wait for the normal close confirmation.

Discord (`com.hnc.Discord`) has a narrow hide-on-close exception. It must be visible and eligible when the gesture begins, and AX must identify the actual close button on its sole, nonminimized window. A same-process hide notification after the matching normal release may preserve that intent. If macOS marks the app hidden before delivering the notification, the verified attempt waits within its original expiry; the state bit alone never authorizes a quit. Reliable snapshots must show either the original retained, nonminimized singleton window or a genuine closed window, without sheets or replacements, for the unchanged confirmation interval. Multiple initial windows disqualify this exception even in any-window mode. Unhiding, subsequent clicks or key presses, expiry, permission/settings changes, or changing window state invalidate it. Final eligibility still checks identity, exclusions, protection, launch state, and the recorded hide transition. Force quit never receives this exception.

The adapter runs synchronous Accessibility queries and observer registration on one serial background queue, uses short IPC timeouts, and discards stale work. The observer's run-loop source is installed on the main run loop and removed when the decision ends or is invalidated. This observer exists only for a pending normal close decision; the app does not periodically sweep every application.

Close-control capture records the initial AX window set before completing the button proof. This avoids discarding a verified click when a fast-closing empty document disappears immediately after the final button read. Required window and button attributes use public [`AXUIElementCopyMultipleAttributeValues`](https://developer.apple.com/documentation/applicationservices/1462051-axuielementcopymultipleattribute) to reduce round trips. Every required value is validated, including the official close-button identity, subrole, enabled state, frame, modal state and sheet children. Grouped reads are not atomic. Only an unimplemented bulk API permits individual reads within the same deadline; errors, partial results and malformed metadata cannot authorize a close. No document contents, titles or file URLs are consulted, and no editor-specific exception is needed.

Window enumeration can race with native close. If inspecting the clicked window or one of its children returns `invalidUIElement`, one immediate enumeration may confirm that only the clicked window disappeared. The remaining identities must match exactly, and every surviving window is inspected again within the original snapshot budget. This does not retry timeouts, unsupported or malformed values, invalid unrelated windows, or a target that remains present. A fresh complete snapshot still goes through the unchanged 150 ms stable confirmation and 200 ms minimum elapsed time; recovery adds no fixed delay.

The mouse tap has its own main-run-loop source and is removed when monitoring stops or is reconfigured. On a timeout, CallQuits invalidates pending work and only re-enables the tap while the utility is enabled and Accessibility trust remains available. User-requested tap disabling pauses CallQuits until the user enables it again. A local AppKit event monitor cancels pending work when the user interacts with CallQuits itself; it is not the source of cross-application identity.

The finite sampling after a close gesture is intentionally conservative: cancellation, an unreadable live-window snapshot, or evidence of a replacement window ends the request. If a save sheet interrupts the close, resolving the sheet does not revive that earlier intent. The user must make a fresh close-button gesture for another automatic quit attempt.

## Platform boundaries

- The public [annotated session event tap](https://developer.apple.com/documentation/coregraphics/cgeventtaplocation/cgannotatedsessioneventtap) supplies the original `CGEvent`. CallQuits consumes that event directly; it does not derive recipient metadata from an `NSEvent` conversion, which was observed to identify the observing process instead of the actual target.
- [Accessibility hit testing](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition) uses top-left-relative screen coordinates and respects window layering. The original `CGEvent` location already uses the matching global coordinate system.
- Accessibility trust covers event listening; a separate Input Monitoring grant is unnecessary for this design, as explained by [Apple Developer Technical Support](https://developer.apple.com/forums/thread/828052). The app does not request Screen Recording or Full Disk Access.
- Event identity uses `CGEvent`'s target PID and its `mouseEventWindowUnderMousePointerThatCanHandleThisEvent` or `mouseEventWindowUnderMousePointer` fields (92 and 91). An owner lookup must match that exact `CGWindowID`; it never guesses from the current frontmost application or later screen geometry. `NSEvent.windowNumber` is an AppKit window-device number and is never used as recipient identity.
- [AXUIElementSetMessagingTimeout](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout) bounds synchronous Accessibility messaging. A timeout on the system-wide object sets the process default; an element-specific timeout applies to that object.
- [`NSRunningApplication.terminate()`](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()) requests normal termination. [`forceTerminate()`](https://developer.apple.com/documentation/appkit/nsrunningapplication/forceterminate()) is a distinct action reserved for the user's enabled Shift-click gesture.
- [`SMAppService.mainApp`](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp) manages the optional login item. System approval can still be required.

Accessibility is not an atomic window-server transaction. The mouse-down hit test runs asynchronously; a very fast click can close the original window before its close control can be read. In that case CallQuits skips the gesture even if event identity could otherwise be resolved. A target app can also create a window before observer registration or after the final snapshot, omit notifications, or expose incomplete metadata. Unknown results are handled by declining to act, and termination requests still rely on the target application's normal lifecycle. The code never promises universal compatibility or guaranteed quit latency.

## Scope

CallQuits uses public APIs and stores settings locally. It has no network dependency, input injection, continuous window polling, or document-content collection. It runs outside App Sandbox because it needs cross-application Accessibility access, while local builds enable the hardened runtime. Developer ID signing and notarization remain release concerns.
