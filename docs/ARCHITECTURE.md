# Implementation notes

CallQuits separates a deterministic decision policy (`Sources/CallQuitsCore`) from macOS integration and presentation (`Sources/CallQuits`). SwiftPM tests the policy without needing Accessibility permission or terminating a process.

## Verified close actions

1. A public Core Graphics event tap at `.cgAnnotatedSessionEventTap`, placed at `.tailAppendEventTap` with `.listenOnly`, observes original left-button down, up, and drag events. Right-button down, other-button down, and ordinary key-down events cancel pending work without reading their contents. When additional close methods are enabled, a Command chord is checked for a layout-resolved W; all other chords still cancel. No keyboard contents are retained or logged. The tap cannot change or suppress input.
2. `EventIdentity` establishes the original recipient from the native `CGEvent` target process ID or a WindowServer owner lookup for the exact global window ID stamped into that event. Accessibility hit testing must then identify the actual close control and an owner matching that established process. Missing or conflicting metadata means no action.
3. Mouse-up must confirm the original event identity and match the mouse-down's supported modifier intent. If native close already removed the original window's WindowServer entry, an exact matching stamped window ID can carry forward the previously verified owner. A conflicting positive process ID, window ID, or owner always cancels. The attempt retains its original application object, native PID, and bundle identity through AX capture and both quit paths. AppKit object equality and the original PID are checked again because automatic termination can change the process represented by a retained application object. Dragging away, a long hold, bypass modifiers, exclusion changes, and new interactions also invalidate the gesture.
4. For a normal quit, an Accessibility observer subscribes to the target app's window-created notifications. Registration must succeed; unsupported apps are skipped. Sheet-created notifications are also requested where supported, and snapshots check for sheets independently.
5. Normal mode lets the target handle its close. Bounded snapshots verify the original window disappeared, check for sheets and replacement windows, and count all reported windows, including minimized windows and other Spaces. A creation notification invalidates the pending request, including when a new window appears between snapshots.
6. After a stable eligible result, the adapter requests graceful termination. The target app retains its native save/quit behavior. Explicitly enabled Shift-click uses the separate force-termination path after gesture and target verification; it does not wait for the normal close confirmation.

Discord (`com.hnc.Discord`) has a narrow hide-on-close exception. It must be visible and eligible when the gesture begins, and AX must identify the actual close button on its sole, nonminimized window. A same-process hide notification after the matching normal release may preserve that intent. If macOS marks the app hidden before delivering the notification, the verified attempt waits within its original expiry; the state bit alone never authorizes a quit. Reliable snapshots must show either the original retained, nonminimized singleton window or a genuine closed window, without sheets or replacements, for the unchanged confirmation interval. Multiple initial windows disqualify this exception even in any-window mode. Unhiding, subsequent clicks or key presses, expiry, permission/settings changes, or changing window state invalidate it. Final eligibility still checks identity, exclusions, protection, launch state, and the recorded hide transition. Force quit never receives this exception.

Application hide/unhide notifications are scoped to the original attempt's process, including while the mouse is held and while AX capture is pending after release. An unrelated application's visibility change cannot cancel the attempt or authorize a hidden-state exception.

The adapter runs synchronous Accessibility queries and observer registration on one serial background queue, uses short IPC timeouts, and discards stale work. The observer's run-loop source is installed on the main run loop and removed when the decision ends or is invalidated. With additional close methods enabled, one observer also tracks the eligible active app’s focused window in preparation for a shortcut. This is driven by activation and AX notifications, not periodic polling. The permission timer never enumerates windows. Pausing, permission loss, monitoring failure, sleep, and reconfiguration clear the cached observation. The prepared observer transfers into a verified keyboard attempt, avoiding observer registration after an immediate ⌘W has already removed the window. Pointer attempts keep their own observer and button proof.

Close-control capture records the initial AX window set before completing the button proof. This avoids discarding a verified click when a fast-closing empty document disappears immediately after the final button read. Required window and button attributes use public [`AXUIElementCopyMultipleAttributeValues`](https://developer.apple.com/documentation/applicationservices/1462051-axuielementcopymultipleattribute) to reduce round trips. Every required value is validated, including the official close-button identity, subrole, enabled state, frame, modal state and sheet children. Grouped reads are not atomic. Only an unimplemented bulk API permits individual reads within the same deadline; errors, partial results and malformed metadata cannot authorize a close. No document contents, titles or file URLs are consulted, and no editor-specific exception is needed.

Window enumeration can race with native close. If inspecting the clicked window or one of its children returns `invalidUIElement`, one immediate enumeration may confirm that only the clicked window disappeared. The remaining identities must match exactly, and every surviving window is inspected again within the original snapshot budget. This does not retry timeouts, unsupported or malformed values, invalid unrelated windows, or a target that remains present. A fresh complete snapshot still goes through the unchanged 150 ms stable confirmation and 200 ms minimum elapsed time; recovery adds no fixed delay.

The mouse tap has its own main-run-loop source and is removed when monitoring stops or is reconfigured. On a timeout, CallQuits invalidates pending work and only re-enables the tap while the utility is enabled and Accessibility trust remains available. User-requested tap disabling pauses CallQuits until the user enables it again. A local AppKit event monitor cancels pending work when the user interacts with CallQuits itself; it is not the source of cross-application identity.

The finite sampling after a close gesture is intentionally conservative: cancellation, an unreadable live-window snapshot, or evidence of a replacement window ends the request. If a save sheet interrupts the close, resolving the sheet does not revive that earlier intent. The user must make a fresh supported close action for another automatic quit attempt.

## Tabs and ⌘W

`CloseTrigger` keeps tab buttons and keyboard shortcuts on last-window graceful quit, regardless of the red button's configured mode. Neither can authorize force quit or Discord's hidden-window exception. The `additionalCloseMethods` preference is enabled by default starting in v0.1.5 and can be disabled independently.

Tab clicks keep the existing native down/up identity, modifier, movement, freshness and AX window checks. The hit must be a button inside a radio-button tab inside a native tab group. Only bounded group, toolbar or scroll-area ancestors may lead from that group to the same window; a web area's controls cannot qualify. An explicit tab `AXCloseButton` relationship is accepted. For providers such as Chromium that expose only the button's accessible name, the exact labels “Close” and “Close tab” are supported. Other localized labels are skipped. Tab titles and page contents are never read. The browser must close the window when its last tab closes; an empty retained browser window still counts.

Brave can return a leaf rendering group from hit testing while exposing the semantic tab group as its immediate sibling. For that exact structure, capture resolves one tab and one close button whose real AX frames contain the event point. It verifies the hit's parent membership, every direct parent relationship, the same native window owner, and the existing native ancestry and close-button semantics. Multiple matching groups, tabs or buttons, unreadable attributes, web ancestors and clicks outside the close button reject capture. This is a bounded sibling lookup, never a window-wide search or a guessed close-button location. The normal capture budget and confirmation delays are unchanged. Chromium's [macOS Accessibility hit-test implementation](https://github.com/chromium/chromium/blob/main/ui/accessibility/platform/ax_platform_node_cocoa.mm) visits children in reverse order, consistent with the observed rendering-group hit.

⌘W requires a positive native event PID. The active-app window cache is only preparation, never recipient evidence. Its captured PID and bundle ID, current application object, and AX window must still belong to the event recipient. The character comes from the original event, with AppKit's layout-aware `charactersIgnoringModifiers` as a fallback; the reconstructed AppKit event is never used for ownership. Missing text, repeats, Shift, Option and Control reject the shortcut rather than guessing a physical QWERTY key.

A matched shortcut consumes the cached observer and starts a bounded attempt. Target-destroy notification can begin checking immediately. Some apps retain closed native windows, so the existing 100 ms sampling cadence provides a fallback before reading during native key handling. The ordinary 150 ms stable confirmation, 200 ms minimum session duration, snapshot freshness checks and original input expiry remain intact. Focus changes cancel cached preparation, but focus changes caused by a matched close do not cancel the subsequent window-state check. Sheets and new windows still cancel it. Canceled or completed attempts replenish the active-app cache, so consecutive tab closes do not require switching apps. No idle window disappearance starts a quit attempt.

The reference implementation's 350 ms first probe plus 1.2-second passive confirmation explains its code-derived 1.55-second minimum request path. CallQuits uses its own policy and observer lifetime instead of importing that subsystem or its private Space APIs. See [fixture measurements and compatibility limits](TESTING.md#tabs-and-shortcuts-development-checks--october-18-2026).

Research references: Apple's [observer registration](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification), [bounded AX messaging](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout), and [normal termination](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()) contracts; Chromium's [tab close-button implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/ui/views/tabs/tab/tab_close_button.cc), which assigns the localized Close name. Apple documents that sending a termination request may precede actual process exit; neither point measures Dock indicator disappearance.

## Platform boundaries

- The public [annotated session event tap](https://developer.apple.com/documentation/coregraphics/cgeventtaplocation/cgannotatedsessioneventtap) supplies the original `CGEvent`. CallQuits consumes that event directly; it does not derive recipient metadata from an `NSEvent` conversion, which was observed to identify the observing process instead of the actual target.
- [Accessibility hit testing](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition) uses top-left-relative screen coordinates and respects window layering. The original `CGEvent` location already uses the matching global coordinate system.
- Accessibility trust covers event listening; a separate Input Monitoring grant is unnecessary for this design, as explained by [Apple Developer Technical Support](https://developer.apple.com/forums/thread/828052). The app does not request Screen Recording or Full Disk Access.
- Event identity uses `CGEvent`'s target PID and its `mouseEventWindowUnderMousePointerThatCanHandleThisEvent` or `mouseEventWindowUnderMousePointer` fields (92 and 91). An owner lookup must match that exact `CGWindowID`; it never guesses from the current frontmost application or later screen geometry. `NSEvent.windowNumber` is an AppKit window-device number and is never used as recipient identity.
- [AXUIElementSetMessagingTimeout](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout) bounds synchronous Accessibility messaging. A timeout on the system-wide object sets the process default; an element-specific timeout applies to that object.
- [`NSRunningApplication.terminate()`](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()) requests normal termination. [`forceTerminate()`](https://developer.apple.com/documentation/appkit/nsrunningapplication/forceterminate()) is a distinct action reserved for the user's enabled Shift-click gesture.
- [`SMAppService.mainApp`](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp) manages the optional login item. System approval can still be required.

Accessibility is not an atomic window-server transaction. The mouse-down hit test runs asynchronously; a very fast click can close the original window before its close control can be read. In that case CallQuits skips the gesture even if event identity could otherwise be resolved. A target app can also create a window before observer registration or after the final snapshot, omit notifications, or expose incomplete metadata. Unknown results are handled by declining to act, and termination requests still rely on the target application's normal lifecycle. The code never promises universal compatibility or guaranteed quit latency.

AX enumeration counts the windows an application exposes, not every retained native window object or document. Native tab groups can expose only the selected tab; closing it can reveal another AX identity and conservatively cancel even in any-window mode. Ordered-out windows can be absent from the AX list. These measured limits and the wider lifecycle audit are recorded in the [October 17 investigation](INVESTIGATION-2026-10-17.md).

## Scope

CallQuits uses public APIs and stores settings locally. It has no network dependency, input injection, continuous window polling, or document-content collection. It runs outside App Sandbox because it needs cross-application Accessibility access, while local builds enable the hardened runtime. Developer ID signing and notarization remain release concerns.
