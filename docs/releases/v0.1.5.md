# CallQuits 0.1.5

Close the last window with a native tab's × or ⌘W, open Accessibility permissions directly, and see more settings without scrolling.

## Highlights

- **Close tabs and use ⌘W:** A new setting, enabled by default, recognizes supported native tab-close buttons and ⌘W. Both request a normal quit only after the last window closes. Remaining tabs and windows keep the app running.
- **Browser tab-close identification:** Handles the Accessibility layout observed in Brave, where hit testing returns the tab area beside the accessible tab group. CallQuits still verifies the actual Close button, its window, and the original event recipient.
- **Accessibility Settings shortcut:** Open the macOS permission page from every settings pane, including after access has been granted.
- **More useful settings space:** Reduced excess top spacing and removed the decorative banner. Standard behavior settings fit without scrolling at the default and minimum window sizes, with room around each control.

Tabs and ⌘W never use any-window mode or force quit. Save dialogs, replacements, minimized windows, exclusions, and uncertain Accessibility state still prevent automatic quitting. Confirmation intervals are unchanged. These tab and shortcut features were not included in the v0.1.4 download.

## Download & install

**Apple silicon (arm64) · macOS 14 or later · Build 6**

The app and DMG are Developer ID signed, notarized by Apple, and carry stapled notarization tickets.

[Download CallQuits 0.1.5 DMG](https://github.com/Mxlted/CallQuits/releases/download/v0.1.5/CallQuits-0.1.5-macos-arm64.dmg) · [SHA-256 checksum](https://github.com/Mxlted/CallQuits/releases/download/v0.1.5/SHA256SUMS.txt)

1. Quit your existing CallQuits copy and open the DMG.
2. Drag `CallQuits.app` to **Applications**, replace the old copy if prompted, and eject the disk image.
3. Open CallQuits from Applications. Use **Accessibility Settings** in its settings sidebar to enable access, and check for **Watching close buttons**. Launch at login may need separate Login Items approval.

**Upgrading from v0.1.0?** The signing identity changed. If Accessibility access stops working, quit CallQuits, remove its old Accessibility entry, add the current app from Applications, enable it, and relaunch. See [installation and permission help](https://github.com/Mxlted/CallQuits/blob/v0.1.5/docs/HELP.md).

- Both Apple notarizations were Accepted with no reported issues. Strict signatures, both stapled tickets, DMG integrity and checksum checks passed. - A disposable native fixture reproduced Brave's tab-area hit testing. The earlier capture code rejected all eight trials; the updated capture accepted all eight and reached the unchanged quit decision after the last window closed. Remaining tabs, visible or minimized second windows, replacement windows, and native save sheets prevented a quit decision. An existing sheet, a point on the tab body, and disabled additional close methods prevented capture.
- Those checks used real application-scoped self-Accessibility and the fixture's native Close button action. Earlier development checks exercised ⌘W and tab-close input through a fixture-only monitor. Neither establishes physical Brave clicks through the final release, full browser compatibility, or measured Dock disappearance.
- Very fast clicks that destroy a control before it can be verified still skip automatic quit. Unsupported localized Close labels, unknown native controls, and web-page buttons do not qualify. A browser that retains an empty window remains running.
- Settings were rendered with an isolated, paused model and no monitor. Standard controls fit at the default and minimum sizes; extra permission-recovery notices can still require scrolling. The Accessibility Settings link reached the permission page without changing any grants.
- Physical browser and editor checks, the full live matrix, macOS 14/Intel runtime, and fresh-install/upgrade checks on a separate Mac/account remain incomplete. This download contains only Apple silicon code; a deployment target or notarization does not establish those runtime results.
- Activity remains bounded and session-only, without document names, window titles, or click histories.
