# CallQuits 0.1.3

Fixes a window-closing race that could leave an app running with **Accessibility could not reliably confirm the window state** in Activity. This addresses a failure reproduced while investigating intermittent Chrome closing.

## Highlights

- **More reliable close confirmation:** If the clicked window disappears while CallQuits is inspecting it, one immediate fresh window-list read can confirm that close. Every other window must still be accounted for and inspected.
- **No added delay:** Recovery does not add a timer or extend the read budget. The existing short confirmation intervals are unchanged.
- **Safety checks preserved:** Sheets, replacement windows, changed surviving windows, and other Accessibility failures still block automatic quit. Discord's normal hide-on-close support remains in place.

## Download & install

**Apple silicon (arm64) · macOS 14 or later · Build 4**

Developer ID signed, notarized by Apple, and shipped with a stapled notarization ticket.

[Download CallQuits 0.1.3](https://github.com/Mxlted/CallQuits/releases/download/v0.1.3/CallQuits-0.1.3-macos-arm64.zip) · [SHA-256 checksum](https://github.com/Mxlted/CallQuits/releases/download/v0.1.3/SHA256SUMS.txt)

1. Quit your existing CallQuits copy, extract the ZIP, and move `CallQuits.app` to **Applications**.
2. Open it and enable **System Settings → Privacy & Security → Accessibility**.
3. Check that CallQuits says **Watching close buttons**. Launch at login may need separate Login Items approval.

**Upgrading from v0.1.0?** The signing identity changed. If Accessibility access stops working, quit CallQuits, remove its old Accessibility entry, add the current app from Applications, enable it, and relaunch. See [installation and permission help](https://github.com/Mxlted/CallQuits/blob/v0.1.3/docs/HELP.md).

This download is Apple silicon only. macOS 14 and Intel runtime behavior, plus fresh-install and upgrade permission behavior on a separate Mac/account, remain unverified. Intel users can try a source build.

<summary>Technical details, validation & known limitations</summary>

- **Narrow recovery:** Only an invalid Accessibility element in the verified clicked window permits a fresh enumeration. The target must be absent and the surviving identities unchanged. Every survivor is inspected again within the original budget. Timeouts, unsupported values, unreadable surviving windows, and repeated failures still cancel.
- **Fixture evidence:** A controlled native/self-Accessibility fixture reproduced the closing-window race. The previous adapter canceled in 8 of 8 repetitions; the updated adapter recovered complete snapshots and reached a quit decision in 8 of 8. Sheets, other windows, replacements, and unrelated errors continued to block quitting.
- **Timing limits:** Fixture policy decisions took 211–220 ms from snapshot processing, with the existing 150 ms stable confirmation and 200 ms minimum unchanged. These are not physical Chrome click-to-quit, process-exit, or Dock-disappearance measurements.
- **Automated coverage:** All 77 debug XCTest cases passed, including the new snapshot recovery and failure-boundary tests. Injected AX reads and simulated policy states do not validate physical event capture or observer delivery.
- **Release verification:** The final Developer ID build, strict signature checks, Apple notarization (Accepted, no reported issues), and stapled-ticket validation passed. Fresh ZIP extraction preserved executable permissions, signature, and ticket; the checksum verified. `syspolicy_check distribution` passed. `spctl` reported a security-disabled override, so default Gatekeeper enforcement was not tested.
- **Remaining validation:** Physical Chrome verification, the full live fixture matrix, macOS 14/Intel runtime checks, and separate-Mac/account installation and upgrade checks remain incomplete. Missing metadata, unsupported window notifications, very fast clicks, or unresponsive apps can still prevent automatic quit.
- **Quit behavior and privacy:** Normal close/save behavior is preserved. Force quit remains opt-in and Shift-click only. Activity stays bounded and session-only, without window titles, document names, or click histories.

See the [testing record](https://github.com/Mxlted/CallQuits/blob/v0.1.3/docs/TESTING.md) for coverage and observed results. Use the checksum file from this release to verify its ZIP.
