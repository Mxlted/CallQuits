# CallQuits 0.1.1

Reliability and recovery improvements, with the same small menu bar feature set. Version **0.1.1**, build **2**, from `Resources/Info.plist`.

## What's changed

- Ineligible and excluded apps are rejected before expensive Accessibility hit testing. Verified event ownership and the final safety checks still guard both quit paths.
- **Retry monitoring** is available when CallQuits is enabled and Accessibility access is granted but click monitoring is unavailable. Failed event-tap setup or re-enabling is reported accurately, with permission-recovery help. Intentional pause and disabled states are preserved.
- Launch-at-login status clears stale approval/error messages. Automatic and manual Accessibility refreshes now report the same meaningful state changes in Activity.
- Activity explains verified close cancellations, including remaining windows, observed sheets or replacements, unreliable Accessibility information, changing window sets, and expiry. It does not claim that a user canceled a dialog without evidence.
- Validation, version metadata, and release preparation are simpler to maintain. CI retains one macOS validation job; downloadable development artifacts are produced only on manual dispatch.

Confirmation and safety delays are unchanged. Normal close/save behavior, protected apps, exclusions, minimized windows, and windows on other Spaces remain part of the safety policy. Force quit remains opt-in and Shift-click only, with the unsaved-work warning. Activity remains bounded, session-only, and free of window titles, document names, and click histories.

## Requirements and setup

The attached `CallQuits-0.1.1-macos-arm64.zip` requires **Apple silicon and macOS 14 or later**. It is not a universal binary. Intel runtime behavior has not been tested; Intel users can try a source build.

**Developer ID signed and notarized by Apple.** The app includes a stapled notarization ticket. Extract the ZIP, move `CallQuits.app` to Applications, and open it normally. Enable **System Settings → Privacy & Security → Accessibility**. Launch at login may require separate Login Items approval.

Quit the old app before replacing it. When upgrading from ad hoc-signed v0.1.0, check Accessibility and monitoring status. If access fails, quit CallQuits, remove its stale Accessibility entry, add the current copy from Applications, enable it, and relaunch. See [installation and permission help](https://github.com/Mxlted/CallQuits/blob/v0.1.1/docs/HELP.md).

## Validation and limitations

- The Developer ID release build, strict signature verification, Apple notarization (Accepted, with no reported issues), stapled-ticket validation, and macOS pre-distribution checks passed. Fresh ZIP extraction preserved executable permissions and the valid signature and ticket; the final archive checksum also verified.
- All **50 XCTest cases passed**, covering event identity, application eligibility, close confirmation and cancellation, settings status, and simulated monitoring recovery. These tests do not drive physical clicks, the real event tap, or Accessibility observers.
- Runtime compatibility on macOS 14 and Intel remains unverified. Fresh-install and upgrade permission behavior on a separate Mac/account remains unverified.
- The full live disposable-fixture matrix remains incomplete, including save cancellation, replacement windows, minimized windows, other Spaces, exclusions on both quit paths, and monitoring recovery.
- No click-to-quit-request, process-exit, or visible Dock-disappearance timings were collected for this release. Reduced Accessibility work is an expected benefit, not a measured latency improvement. Deadline, observer, and concurrency optimizations remain deferred pending measurements.
- Incomplete Accessibility metadata, unsupported window notifications, very fast clicks, or unresponsive apps can prevent automatic quit. CallQuits skips uncertain attempts. Keyboard, menu, and programmatic closes do not trigger it.

See the [testing record](https://github.com/Mxlted/CallQuits/blob/v0.1.1/docs/TESTING.md) for the distinction between simulated coverage and observed live results. `SHA256SUMS.txt` verifies the final delivered ZIP; download both assets from the same release.
