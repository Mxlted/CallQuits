# CallQuits 0.1.0

Initial private development release. Version **0.1.0**, build **1**, from `Resources/Info.plist`.

## Features

- A verified click on an app's red close button requests a graceful quit after its last window closes. An optional mode applies after any window closes.
- Pause controls, editable app exclusions, and launch at login. Finder, system processes, and CallQuits stay protected.
- Optional Shift-click force quit, disabled by default and guarded by an unsaved-work warning. A normal quit never escalates to force quit.
- New original icon: a coral close button and power mark on a dark window, also used in settings.

## Requirements and setup

The attached ZIP requires **Apple silicon (arm64) and macOS 14+**. It is not a universal binary; Intel users can build from source.

Extract the ZIP and move `CallQuits.app` to `/Applications`. Launch it, then enable **System Settings → Privacy & Security → Accessibility**. Relaunch if needed. Ad hoc app replacements can leave stale permission entries; remove the old entry and add the current app again if access fails. Launch at login may need separate Login Items approval.

**Ad hoc signed; not notarized.** No valid Apple signing identity was available for this build. It has no verified Developer ID or stapled notarization ticket, so Gatekeeper may block first launch.

## Validation and limitations

- All **40 Swift policy tests passed**, covering event identity, click/modifier matching, protected apps, close cancellation, sheets, replacement windows, and unreadable snapshots.
- Release build, `git diff --check`, bundle metadata, and strict code-signature verification passed. ZIP extraction preserved executable permissions, app contents, and the signature. `SHA256SUMS.txt` supplies the archive's SHA-256 checksum.
- Validation ran on Apple silicon with macOS 27.0.1 and Swift 6.4. Runtime compatibility on macOS 14 and Intel was not tested for this artifact.
- Live physical-click, save-dialog, multiple-window, minimized-window, Spaces, and force-quit checks remain incomplete. Automated policy tests do not establish full Accessibility integration coverage or Dock disappearance timing.
- Missing or unusual Accessibility metadata, unsupported window notifications, very fast clicks, and unresponsive apps can prevent automatic quit. Keyboard, menu, and programmatic closes do not trigger it.
