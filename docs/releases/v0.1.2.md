# CallQuits 0.1.2

Discord now supports a normal red-button close without holding Shift, including when it hides its main window during closing.

## Highlights

- **Discord normal close:** CallQuits can request a graceful quit after a verified close-button click hides Discord's only, non-minimized window. This applies to the standard Discord app and still requires native event ownership, Accessibility verification, and stable window checks.
- **Keyboard interruption:** Pressing a key cancels a pending close attempt. CallQuits only detects that a key was pressed; it does not read or record keycodes, characters, or recipients.
- **Safety checks preserved:** Sheets, extra or replacement windows, unreliable Accessibility data, and expired intent block the pending quit. Protected apps, exclusions, minimized windows, and windows on other Spaces remain covered. Confirmation delays are unchanged, and normal close never escalates to force quit.

## Download & install

**Apple silicon (arm64) · macOS 14 or later · Build 3**

Developer ID signed, notarized by Apple, and shipped with a stapled notarization ticket.

[Download CallQuits 0.1.2](https://github.com/Mxlted/CallQuits/releases/download/v0.1.2/CallQuits-0.1.2-macos-arm64.zip) · [SHA-256 checksum](https://github.com/Mxlted/CallQuits/releases/download/v0.1.2/SHA256SUMS.txt)

1. Quit your existing CallQuits copy, extract the ZIP, and move `CallQuits.app` to **Applications**.
2. Open it and enable **System Settings → Privacy & Security → Accessibility**.
3. Check that CallQuits says **Watching close buttons**. Launch at login may need separate Login Items approval.

**Upgrading from v0.1.0?** The signing identity changed. If Accessibility access stops working, quit CallQuits, remove its old Accessibility entry, add the current app from Applications, enable it, and relaunch. See [installation and permission help](https://github.com/Mxlted/CallQuits/blob/v0.1.2/docs/HELP.md).

This download is Apple silicon only. macOS 14 and Intel runtime behavior, plus fresh-install and upgrade permission behavior on a separate Mac/account, remain unverified. Intel users can try a source build.

<summary>Technical details, validation & known limitations</summary>

- **Discord checks:** The same process must hide after mouse release, and its retained window must remain the only, non-minimized window across stable Accessibility snapshots. Unhide, changed eligibility, sheets, extra/replacement windows, unreliable snapshots, or expired intent cancel the attempt.
- **Quit behavior and privacy:** Normal close/save behavior is preserved. Force quit remains opt-in and Shift-click only, with an unsaved-work warning. Activity is bounded and session-only, without window titles, document names, or click histories.
- **Release verification:** The final Developer ID build, strict signature checks, Apple notarization (Accepted, no reported issues), and stapled-ticket validation passed. Fresh ZIP extraction preserved executable permissions, signature, and ticket; the checksum verified. `syspolicy_check distribution` passed. `spctl` reported a security-disabled override, so default Gatekeeper enforcement was not tested.
- **Automated coverage:** All **63 debug XCTest cases passed**, including hidden-state eligibility, expiry, window/dialog protection, and final eligibility checks. These simulate states; they do not exercise physical clicks, the event tap, or Accessibility observers.
- **Fixture checks:** A disposable native/self-Accessibility fixture reproduced retained windows after hiding. Probes using the unchanged production snapshot and policy code reached stable confirmation and graceful quit for one clean hidden window; sheets and two retained windows blocked it. Verified-click qualification was injected into the probes, so event capture and observer delivery were not validated.
- **Observed Discord result:** A physical red-button click without Shift quit Discord **0.0.416 with Equicord** on the preceding development build using the same application code. Activity recorded **Asked Discord to quit**, and a process check confirmed exit. This was one successful case, not a test of every Discord version, release channel, window arrangement, or the final archive.
- **Remaining validation:** The full live fixture matrix, keyboard-interruption delivery, and both hide-notification orderings through the complete monitor remain incomplete. No precise click-to-quit-request, process-exit, or Dock-disappearance timings were collected; no measured latency improvement is claimed.
- **Compatibility limits:** Missing Accessibility metadata, unsupported window notifications, very fast clicks, or unresponsive apps can prevent automatic quit. CallQuits skips uncertain attempts. Keyboard, menu, and programmatic closes do not trigger it.

See the [testing record](https://github.com/Mxlted/CallQuits/blob/v0.1.2/docs/TESTING.md) for coverage and observed results. Use the checksum file from this release to verify its ZIP.
