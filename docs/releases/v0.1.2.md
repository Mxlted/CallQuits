# CallQuits 0.1.2

Normal close now handles Discord hiding its main window, so a verified red-button click can request a graceful quit without Shift. Version **0.1.2**, build **3**, from `Resources/Info.plist`.

## What's changed

- Discord can quit normally when its only window hides after a verified red-button click. CallQuits still requires matching native mouse-event identity, positive Accessibility identification of the close button, and an observed hide of that same process after mouse release.
- The retained Discord window must be the only window, must not be minimized, and must pass stable Accessibility checks. Sheets, replacement or extra windows, unreliable snapshots, unhide, expired intent, and changed eligibility prevent the pending quit. This allowance is scoped to the standard Discord app.
- Pressing a key cancels a pending close attempt, including while waiting for Discord's hide notification. Only the occurrence of a key press is used; keycodes, characters, and recipients are not read or recorded.

Confirmation and safety delays are unchanged. Normal close/save behavior, protected apps, exclusions, minimized windows, and windows on other Spaces remain part of the safety policy. A normal close never escalates to force quit. Force quit remains opt-in and Shift-click only, with the unsaved-work warning. Activity remains bounded and session-only, without window titles, document names, or click histories.

## Requirements and setup

The attached `CallQuits-0.1.2-macos-arm64.zip` requires **Apple silicon and macOS 14 or later**. It is not a universal binary. Intel runtime behavior has not been tested; Intel users can try a source build.

**Developer ID signed and notarized by Apple.** The app includes a stapled notarization ticket. Extract the ZIP, move `CallQuits.app` to Applications, and open it normally. Enable **System Settings → Privacy & Security → Accessibility**. Launch at login may require separate Login Items approval.

Quit the old app before replacing it, then check Accessibility and monitoring status. When upgrading from ad hoc-signed v0.1.0, the signing identity changes. If access fails, quit CallQuits, remove its stale Accessibility entry, add the current copy from Applications, enable it, and relaunch. See [installation and permission help](https://github.com/Mxlted/CallQuits/blob/v0.1.2/docs/HELP.md).

## Validation and limitations

- The final Developer ID release build, strict signature verification, Apple notarization (Accepted, no reported issues), and stapled-ticket validation passed. Fresh ZIP extraction preserved executable permissions, signature, and ticket; its checksum verified. `syspolicy_check distribution` passed. `spctl` identified Notarized Developer ID but reported a security-disabled override, so default Gatekeeper enforcement was not tested.
- All **63 debug XCTest cases passed** during final release preparation, including the scoped hidden-state allowance, expiry, window and dialog protection, and final eligibility boundaries. These tests use simulated states; they do not drive physical clicks, the real event tap, or Accessibility observers.
- Disposable native/self-Accessibility fixture checks reproduced a retained window after hiding. Separate probes compiled the production snapshot and policy code unchanged, with verified-click qualification injected only into the probe: a clean hidden window reached stable confirmation and a graceful quit, while sheets and two retained windows blocked it. These probes did not validate the event-capture or observer-delivery path.
- On the preceding development build with the same application code, the user physically clicked Discord's red close button without Shift and reported a normal quit. Activity recorded **Asked Discord to quit**, and a read-only process check found no Discord main application running. This is one successful case with Discord **0.0.416 and Equicord**, not a guarantee across Discord versions, release channels, or window arrangements.
- The full live disposable-fixture matrix remains incomplete. Keyboard-interruption delivery and both hide-notification orderings through the complete monitor still need live validation. Runtime compatibility on macOS 14 and Intel, and first-install and upgrade permission behavior on a separate Mac/account, remain unverified.
- No precise click-to-quit-request, process-exit, or visible Dock-disappearance timings were collected. Confirmation delays were not shortened, and no measured latency improvement is claimed.
- Incomplete Accessibility metadata, unsupported window notifications, very fast clicks, or unresponsive apps can prevent automatic quit. CallQuits skips uncertain attempts. Keyboard, menu, and programmatic closes do not trigger it.

See the [testing record](https://github.com/Mxlted/CallQuits/blob/v0.1.2/docs/TESTING.md) for simulated coverage and observed live results. `SHA256SUMS.txt` verifies the final delivered ZIP; download both assets from the same release.
